# Инженерные инструкции 4FusionLab

[English](AGENTS.md)

Этот репозиторий содержит переиспользуемые компоненты CI **только для чтения** и общие настройки организации. Инструкции конкретного продукта находятся в его репозитории.

## Язык и документация продуктов

- При создании или изменении README продукта следуйте [правилам README](README_GUIDELINES.ru.md), включая соответствие языковых версий и проверку лицензии.
- Документы ведутся на английском; для документации поддерживаются отдельные русские версии. Промежуточные рабочие заметки переводить не требуется.
- Обсуждайте требования и планы на русском. Используйте английский для подписей интерфейса Autodesk Fusion, стабильных API-идентификаторов и публичных имён входов Actions.
- Сохраняйте раздельную документацию EN/RU, если у продукта уже есть обе версии. Не заменяйте незаметно ни один язык спойлерами или машинными заглушками.
- Соблюдайте существующие архитектуру продукта, условия UX, тесты и оговорки о совместимости CAD.

## Git, CI и выпуск

- Для изменений CI и публикации предпочитайте небольшой проверенный PR. Не используйте force-push и не изменяйте опубликованную историю. Сохраняйте возможность прямого push в main, где это разрешено настройками репозитория.
- Не создавайте теги релизов вручную. Push или объединение PR в `main` может опубликовать релиз **только при изменении поставляемых исполняемых файлов после последнего опубликованного Release**. Push только документации может восстановить ранее неудавшийся выпуск, но никогда не должен создавать релиз сам по себе. См. [`RELEASE_RECOVERY.ru.md`](RELEASE_RECOVERY.ru.md).
- Сохраняйте `.github/release-paths.txt` каждого репозитория как проверенный перечень путей, дающих право на релиз. Изменения только README, документации, тестов, workflow, политик и AGENTS.md не должны создавать GitHub Release.
- GitVersion.Tool закреплён за **6.8.2**. Требуется полная история Git. Опубликованные теги, релизы и загруженные артефакты неизменяемы; не переназначайте теги, не перезаписывайте артефакты и не переводите предварительный выпуск в Stable как понижение версии.
- Основные общие Actions находятся в `.github/actions/` и должны закрепляться потребителями за точным SHA коммита. Не используйте движущуюся ветку `main` в рабочих заданиях релиза.
- Закрепляйте официальные `actions/*` за точными проверенными SHA из [`ACTIONS_PINS.ru.md`](ACTIONS_PINS.ru.md). Перед обновлением сверяйте вышестоящие теги; не используйте плавающие теги основных версий в workflow продукта.
- `contents: write` требуется только заданиям публикации; тесты пакета, проверка метаданных и задания PR работают с минимальными правами чтения.
- Успешная автономная сборка или тест Python **не** подтверждает приёмку CAD в Autodesk Fusion. Сохраняйте свидетельства проверок на платформах и условия безопасности и совместимости.

## Качество

- Проверяйте общие Actions командой `python -m unittest discover -s .github/tests -v` и workflow проверок общей платформы релизов.
- Для изменения Actions сначала объедините проверенный PR платформы, затем переводите потребителей отдельными PR с успешным CI проекта. Не меняйте исполняемый код продукта в рамках миграции CI.
- Перед заменой команд упаковки продукта проверьте содержимое ZIP, версию манифеста, SHA-256, заметки и различия ОС для этого продукта.
- Никогда не размещайте в этом публичном репозитории учётные данные, секреты, личные CAD-файлы, машинные пути или проприетарные материалы.

## Совместимость

- Сохраняйте стабильные UUID манифестов Fusion, идентификаторы команд, названия продуктов, ресурсы платформ, метаданные поддерживаемых ОС и формат установки каждого репозитория.
- `AGENTS.md` на уровне проекта дополняет эти общие ожидания и остаётся основным источником для ограничений API, геометрии и UX конкретного проекта.
