## Правила сопровождения

1. Сохраняйте существующую архитектуру и CI продукта для каждой ОС. Обновление официального Action относится только к инфраструктуре и само по себе **не должно** менять `.github/release-paths.txt` или публиковать GitHub Release.
2. По возможности обновляйте Actions вместе, создавая один удобный для проверки PR на репозиторий. Перед объединением проверяйте фактический CI PR, включая требования к ZIP и SHA-256; затем проверяйте запуски `main` и пропущенные шаги публикации.
3. Разрешение `contents: write` нужно только заданиям релиза продукта. Для обычного CI оставляйте `contents: read`; при checkout задавайте `persist-credentials: false`, кроме случаев, когда конкретная разрешённая запись требует другого.
4. Не развёртывайте автоматически демо Filamentra-DataSource в GitHub Pages при обновлении закреплённых версий. Его workflow намеренно запускается вручную.
5. Общие составные Actions 4FusionLab поддерживаются отдельно: потребители закрепляют `4FusionLab/.github/.github/actions/*` за проверенным SHA коммита платформы. GitVersion.Tool остаётся версии `6.8.2`.
6. При изменении закрепления определите тег в исходном GitHub-репозитории, изучите несовместимые изменения, обновите эту таблицу и PR потребителей и сохраняйте комментарии с версиями рядом с закреплёнными строками `uses:`.
