# Общая платформа релизов

[English](RELEASE_PLATFORM.md)

Централизованные переиспользуемые Actions для репозиториев 4FusionLab. Источник: [4FusionLab/.github](https://github.com/4FusionLab/.github).

## Совместимость и внедрение

| Action | Назначение | Необходимый контекст |
| --- | --- | --- |
| `.github/actions/resolve-version` | GitVersion.Tool **6.8.2**, возвращает числовую версию или SemVer | Полный checkout (`fetch-depth: 0`) |
| `.github/actions/runtime-changes` | Сравнение неопубликованных изменений исполняемых файлов с последним опубликованным ZIP-релизом (по выбору) или исходного диапазона push | Полный checkout, SHA `before` / `after` и `github.token` с правом только на чтение |
| `.github/actions/release-notes` | Использование проверенных заметок версии либо создание из истории | Полный checkout и доступный для записи файл в `runner.temp` |
| `.github/actions/verify-archive` | Проверка ZIP, SHA-256, необязательного манифеста Fusion и непустых заметок | Собранные ZIP-архивы и файлы контрольных сумм |

**Закрепляйте ссылку на Action за точным SHA объединённого коммита платформы**, а не за `@main` или изменяемым тегом. После успешных тестов платформы открывайте отдельный PR потребителя.

### Пример проверки права на релиз без записи

```yaml
- uses: actions/checkout@<approved-immutable-sha>
  with:
    fetch-depth: 0
    persist-credentials: false
- id: changes
  uses: 4FusionLab/.github/.github/actions/runtime-changes@<approved-platform-sha>
  with:
    before: ${{ github.event.before }}
    after: ${{ github.sha }}
    paths-file: .github/release-paths.txt
    recover-unpublished: 'true'
    token: ${{ github.token }}
```

Продукт публикуется только при `push` в `main` после успешных существующих тестов, сборки, подготовки заметок и проверки архива **и** когда Action runtime-changes возвращает `release=true`. PR и `workflow_dispatch` никогда не публикуют релиз. Push только документации может восстановить ранее **пропущенный** выпуск, но не создаёт релиз, если после последнего опубликованного тега-предка нет неопубликованных поставляемых изменений. Без включения `recover-unpublished` по умолчанию сохраняется исходная проверка диапазона push.

### Условия безопасности

- Все составные Actions здесь работают **только на чтение** и не создают теги, GitHub Releases или развёртывания Pages. Финальная публикация GitHub Release остаётся в репозитории продукта с его проверками, правилами каналов и упаковкой.
- Эти Actions не получают разрешение `contents: write`.
- Нельзя перезаписывать ранее опубликованную версию или неизменяемый тег Git, указывающий на другой коммит.
- Изменения тестов, документации и workflows сами по себе не дают права на релиз. Последующий push только документации может повторить выпуск неопубликованных изменений после ошибки CI или публикации. Добавление, удаление и переименование исполняемых файлов остаются основанием для релиза.
- Успешная сборка ZIP в CI не доказывает прохождение нативного интеграционного теста CAD в Fusion.

Подробнее о поведении при ошибках и миграции — в [RELEASE_RECOVERY.ru.md](RELEASE_RECOVERY.ru.md). Для восстановления релизов **не задавайте фильтр `push.paths`** в основном workflow публикации: он заблокирует повторные запуски при изменении только документации.

### Модель выполнения

Репозитории сохраняют существующие матрицы CI для Linux/macOS/Windows, приёмку Fusion, сборщики пакетов и условия публикации. Общие Actions заменяют только дублирующиеся определение версии, фильтрацию путей, создание заметок и проверку архива.

Для сопровождения платформы добавьте регрессионные тесты в `.github/tests`, добейтесь успешного выполнения `.github/workflows/platform-tests.yml`, объедините изменение в репозиторий платформы, закрепите новый SHA в PR потребителей, проверьте все их проверки и только после этого объединяйте их изменения.
